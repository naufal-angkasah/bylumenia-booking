1. VISI PRODUK & LANDASAN BRAND BYLUMENIA
Bylumenia merupakan butik visual pernikahan dan prewedding yang memprioritaskan kedalaman emosi, gestur
mikro, serta keabadian rasa di atas sekadar kuantitas sesi foto massal. Sistem ini dibangun untuk menggantikan
formulir pemesanan konvensional yang kaku menjadi ruang temu yang hangat. Calon klien tidak sekadar mengisi
data administratif, melainkan dihantar melalui narasi puitis yang menyaring kesungguhan visi mereka sebelum
membuka akses investasi dan komitmen jadwal secara resmi.

3. SPESIFIKASI ALUR FORMULIR SINEMATIK KLIEN (5 BABAK)

pemuatan narasi yang menggugah emosi calon pengantin.

5. PENANGANAN VIDEO LATAR BELAKANG (INTEGRASI LINK GOOGLE DRIVE)
Arsitektur Streaming Video Google Drive: Pengembang tidak diperbolehkan memakai elemen iframe pratinjau Drive
karena memunculkan bilah kontrol Google. Gunakan Google Drive File ID yang dikonversi melalui fungsi backend atau API
stream langsung menjadi source URL murni.
Endpoint Pemutar: /api/v1/stream-video?driveId={GOOGLE_DRIVE_FILE_ID}&section={1..5}
Format Output: HTML5 <video autoPlay loop muted playsInline preload="auto">
• Optimasi Bobot: Terapkan teknik lazy-loading sehingga video babak 2 tidak dimuat sebelum babak 1 diselesaikan.
• Fallback Otomatis: Sediakan gambar diam beresolusi tinggi bila kecepatan jaringan pengguna lambat.
• Transisi Mulus: Berikan efek cross-fade opacity selama 800ms ketika pengguna berpindah babak formulir.
6. MODUL PEMBAYARAN & VALIDASI BUKTI TRANSFER
Kanal QRIS & Transfer Bank
• QRIS Interaktif: Kode QR ditampilkan di layar dengan
tombol cepat "Unduh Gambar QR" untuk pembayaran lewat
galeri ponsel.
• Transfer Manual: Menampilkan Rekening BCA dan Mandiri
resmi Lumenia dilengkapi tombol salin satu sentuhan.
• Kode Unik Otomatis: Tambahkan 3 digit acak di belakang
nominal DP (contoh: Rp1.500.412) guna mempermudah
rekonsiliasi manual.
Validasi Berkas & Sapaan Ramah Pengguna
• Filter Upload: Batasi ekstensi ke .jpg, .jpeg, .png, dan .pdf
dengan ukuran maksimal 5 MB.
• Sapaan Validasi: Jika berkas buram atau kosong, ganti
peringatan sistem menjadi kalimat santun: "Foto tanda bukti
belum terbaca jelas, mari coba sematkan sekali lagi."
• Pemicu Webhook: Begitu bukti tersemat, sistem otomatis
mengirimkan data ke kurator tanpa jeda.

7. ARSITEKTUR DASBOR ADMIN (INTERNAL BACKOFFICE)
Dasbor manajemen internal dirancang dengan navigasi sidebar minimalis modern berlatar gelap, memudahkan
kurator memantau jadwal, memveriﬁkasi pembayaran, serta mengubah konten form tanpa menyentuh kode.
Menu Sidebar Fungsi & Tampilan Antarmuka Aksi & Output Operasional
1. Overview Ringkasan metrik (Total Reservasi, Pending
Veriﬁcation, Active Holds, Conﬁrmed) dan kalender
bulanan dengan kode warna.
Klik tanggal pada kalender untuk melihat
daftar nama pasangan yang sedang
menahan atau mengunci hari tersebut.
2. Client Tabel data calon pengantin (ID Booking, Nama,
WhatsApp, Tanggal, Paket, Lokasi, Bukti Bayar,
Status).
Modal pratinjau bukti bayar dengan
tombol zoom, tombol Konﬁrmasi DP, dan
tautan kirim pesan WhatsApp otomatis.
3. Analytic Graﬁk konversi per babak formulir (mendeteksi titik
drop-off) dan persentase preferensi rasa visual
(Teduh vs Anggun vs Riuh).
Evaluasi daya tarik copywriting serta
efektivitas video tiap babak untuk
meningkatkan penyelesaian reservasi.
4. Log Jejak audit sistem: waktu penahanan slot (Hold),
waktu unggah bukti bayar, waktu rilis otomatis
(Expired), dan aksi admin.
Pencatatan transparan untuk mencegah
sengketa jadwal atau kesalahan manusia
saat validasi transfer bank.
5. Form Edit CMS Pengaturan Formulir: Input tautan ﬁle Google
Drive untuk video tiap babak, editor teks narasi puitis,
dan ubah harga paket.
Tim kurator dapat mengganti karya video
atau memperbarui kutipan narasi berkala
tanpa bantuan programmer.
6. Report Laporan keuangan berkala: Rekapitulasi uang muka
masuk, proyeksi pelunasan sebelum hari H, dan
statistik lokasi pernikahan.
Ekspor laporan pembukuan ke format ﬁle
spreadsheet Excel/CSV dan ringkasan
siap cetak.
8. SKEMA BASIS DATA (DATABASE MODELS)
TABLE bookings (
  id UUID PRIMARY KEY, booking_code VARCHAR(20) UNIQUE, couple_name VARCHAR(150),
  whatsapp VARCHAR(25), event_date DATE NOT NULL, event_location VARCHAR(255),
  aesthetic_mood VARCHAR(50), package_name VARCHAR(100), total_price NUMERIC(12,2),
  down_payment NUMERIC(12,2), proof_file_url TEXT, status VARCHAR(30) DEFAULT 'HOLD',
  hold_expires_at TIMESTAMP, created_at TIMESTAMP DEFAULT NOW()
);
TABLE form_configs (section_key VARCHAR(30) PRIMARY KEY, gdrive_video_id TEXT, story_quote TEXT);
TABLE system_logs (id BIGSERIAL PRIMARY KEY, booking_id UUID, action_type VARCHAR(50), executed_by
VARCHAR(50), logged_at TIMESTAMP);
